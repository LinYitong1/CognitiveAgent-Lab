# Code Review

## Overview

对 CognitiveAgent Lab 的代码变更做逐文件评审，拦截安全、正确性与规范问题，保证代码满足项目交付标准后才算任务完成。

## 触发条件

- Backend/Frontend Agent 完成任何编码任务后（合入前强制评审）。
- 用户要求审查代码、检查某次改动。
- 修复 bug 后复评。

## 审查清单（逐项核对）

1. **安全**
   - 无硬编码 API key / 密码 / token；一律 `os.environ` / pydantic-settings。
   - 工具 executor 不执行未声明的系统命令；subprocess 调用有白名单。
   - FastAPI 端点对输入做完整校验，无未捕获异常泄露堆栈。
2. **正确性**
   - 边界条件：空输入、超长输入、工具返回 None/异常时的处理。
   - 状态机：无非法状态迁移；失败路径能把任务置为 `failed` 而非悬挂。
   - 资源释放：数据库连接、文件句柄用 context manager。
3. **规范**
   - 公共函数有类型标注与 docstring。
   - 分层依赖方向正确（api → services → agent → tools/storage，禁止反向 import）。
   - 日志用结构化事件（logger + extra 字段），不用裸 print。
4. **测试**
   - 变更对应测试已更新；`pytest` 全绿。
   - 新分支逻辑（错误路径）有显式用例覆盖。

## 执行流程

1. 获取变更范围：改动文件清单 + 逐文件读取（必要时对比 `docs/ARCHITECTURE.md` 判断是否偏离设计）。
2. 按审查清单逐项检查，记录问题：`位置（文件:行）→ 问题描述 → 严重级别 → 修复建议`。
3. 产出评审结论：`通过 / 退回修改（列出必改项）`。
4. 退回时明确列出必改项；开发者修复后必须复评同一清单。
5. 通过后确认改动文件清单与测试结果，供 Orchestrator 归档。

## 验收标准（本 Skill 的交付标准）

- 审查报告覆盖清单全部 4 大项，无遗漏项静默跳过。
- 每个问题含文件路径与行号定位、修复建议。
- 结论二选一明确给出；退回项全部解决并复评通过后任务方可关闭。
- 评审过程不修改被审代码（评审与修改职责分离）。
