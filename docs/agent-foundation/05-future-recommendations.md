# 05 — Future Recommendations (not implemented this round)

Each item lists the trigger condition that would justify it — none is implemented now.

1. **Context overflow handling & compaction.** Trigger: real-LLM tasks actually hitting provider context limits (observable now via cumulative `usage`). Requirement before implementation: a proof that compaction preserves tool_call/tool_result pairing, tool_call IDs, and provider metadata (Gemini's opaque extensions) — otherwise silent protocol corruption. Preferred minimal form: explicit truncation markers + fail-loud, not silent summarization.
2. **Prompt-injection hardening.** Trigger: real-LLM red-teaming budget. Untested risk, now stated precisely: untrusted tool-result content (HTTP responses from allow-listed hosts, file contents read back) enters the conversation unfiltered; the concrete cross-tool chain is `http_request` (untrusted response) → injected instructions influence the model → `file_read` of sandbox data → exfiltration by embedding that data in a GET URL/query to an allow-listed host (HTTP is GET-only — no request body — and hosts are exact-match allow-listed before DNS, default `example.com`). Hardening options when triggered: tool-result content marking/delimiting, URL length/parameter inspection against sandbox-content fingerprints, and a stricter default allow-list. The eval harness's `s7` only verifies structural pass-through, which is all a scripted LLM can verify.
3. **SQLite persistence / resume / checkpoints.** Trigger: multi-session or long-horizon task management becoming a real requirement. The design already exists in ARCHITECTURE.md §5-§6 (now clearly marked as unimplemented). The JSONL event log already survives kill -9, so recovery semantics — not logging — is the actual gap.
4. **Tool-call budget separate from model-step budget.** Trigger: observed multi-call-per-round abuse in real traces (none observed so far: T5/T2R averaged ~1 call/round).
5. **`validation` event type (public schema change).** Trigger: consumers needing event-level validation verdicts without payload parsing. Deliberately deferred: adding a public event type is a breaking change to the converged event enumeration.
6. **Real-LLM evaluation under the new observability.** Trigger: user authorization + budget. Re-run T5 (expected pass) and T2R (the nominal-manipulation class should now be *detectable in-run* if the model repeats the label-only pattern, and the design-first prompt + P0/P1 primitives give it a real path to content-driven designs). Report termination reasons, usage, durations — all now recorded.

## Architecture deliberately NOT needed

Multi-agent collaboration, a planner/critic split, vector memory, and a graph runtime: the audit found no evidence in the traces (T5/T2R, 10+12 requests) that the single loop's reasoning depth is the binding constraint — tool-surface documentation and design-phase guidance (M3-B) were. Adding orchestration machinery would grow the untested surface without addressing an observed failure.
